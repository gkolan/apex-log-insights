## [1.2.0] - 2026-08-25

### Added

- Evidence-completeness checks that identify Salesforce truncation signals, skipped sections, and missing transaction boundary markers
- Failure context trails that show and link the events immediately preceding captured exceptions
- MCP `compare_logs` tool with explicit candidate-minus-baseline deltas for runtime, CPU, heap, SOQL, DML, callouts, and errors
- CLI `/api/health` endpoint for local diagnostics and automation
- Browser-extension popup action that clears cached log payloads without deleting preferences

- Task-oriented documentation index, getting-started, privacy, troubleshooting, core API, report schema, architecture, and release guides
- Project writing guide for specific, natural, evidence-based documentation and change summaries
- Documentation structure standard and terminology reference adapted from the Record Health Check naming and metadata-writing rules
- Folder-level README pages that explain the API, image, logo, browser-release, and store-documentation collections
- Documentation buckets for user guides, reference material, development guidance, and browser release packages
- `pnpm validate`, documentation consistency checks, version synchronization checks, and GitHub Actions validation and release workflows
- Versioned synthetic fixtures so a fresh clone exercises integration tests reproducibly
- Added an optional `pnpm test:corpus` compatibility gate for Certinia's public large Apex debug-log sample. The runner pins the download by exact size and SHA-256, exercises parsing, canonical report assembly, normalization, and all five views, emits aggregate-only privacy signals, keeps external logs gitignored, and removes newly downloaded data unless retention is explicitly requested.
- Added canonical resource-trajectory and heap-watermark charts, a nested code-unit waterfall, a lifecycle stepper, record-graph drill-downs, and Flow/Workflow execution stories to the shared five-view UI. Large evidence logs remain fully traversable through bounded 500-line pages.
- Added first-class Apex database cursor analysis for `CURSOR_CREATE_BEGIN`, `CURSOR_CREATE_END`, `CURSOR_FETCH`, and `CURSOR_FETCH_PAGE`. Cursor creation spans retain their matched end evidence, while reports expose bounded create/fetch records with query IDs, queries, offsets, row counts, and durations where Salesforce logged them.
- Added direct browser-worker protocol tests for invalid messages, bounded input, and canonical offline-report output.
- Added the initial `packages/vscode-ext/` workspace package with a stable Marketplace identity, restricted-workspace declaration, bundled host entry point, version synchronization, and `.vsix` packaging command. User-facing analysis commands are not implemented yet.
- Added bounded Apex debug-log detection, product-qualified active-file and file-picker commands, contextual menu entries, and an **Analyze with Apex Log Insights** CodeLens to the developing VS Code package.
- Added cancellable VS Code worker-thread parsing with request IDs, a 120-second timeout, canonical offline-report generation, stale-response rejection, and packaged worker verification.
- Added the complete VS Code analysis panel with restrictive local-resource webview policy, canonical five-view rendering, exact log-line navigation, one-panel-per-source reuse, stale-source notices, refresh and retry behavior, VS Code theme integration, and a reproducible standalone VSIX.

### Changed

- Version synchronization now updates standalone-viewer asset markers and the extension popup label as well as packages and manifests
- Documentation identifies one source of truth per topic and distinguishes canonical viewer sources from generated extension assets
- pnpm is the sole supported package manager and lockfile
- Documentation and user-interface copy now follow the project terminology and documentation standards, with task-specific labels, explicit privacy boundaries, and consistent view names
- Product screenshots moved to `assets/images/`; the standalone documentation website and site-only logo assets were removed
- Direct dependencies were updated and vulnerable transitive build dependencies were pinned to patched versions
- Repository-generated audit commands are now `pnpm audit:report` and `pnpm bugs:report`, avoiding pnpm built-in command collisions
- The stable-release checklist now requires validation, dependency audit, a fresh build, a zero-finding bug report, and a zero-violation maintained-source Code Analyzer scan
- Documentation now has a required ten-check structural quality audit, heading-anchor validation, final related-page navigation, a concise test-selection guide, and current VS Code installation and troubleshooting guidance. The VS Code specification now records the implemented `1.2.0` candidate instead of describing it as unshipped work.
- Code Analyzer scan results now belong in the ignored `code-analyzer-output/` directory; the root `code-analyzer.yml` remains the versioned scan configuration.
- The shared viewer UI now uses a Salesforce Cosmos-inspired semantic theme. Night remains the default, while both themes map surfaces, text, accents, borders, feedback states, typography, radii, spacing, and shadows to verified SLDS 2 global styling hooks with local fallbacks.
- The standalone viewer, browser extension, CLI, and VS Code panel now display the same established five-view renderer from `viewer/app.js` and `viewer/index.html`. Shared navigation preserves URL state and exposes expanded state to assistive technology. Responsive layouts keep wide tables locally scrollable and collapse multi-column cards without page-level overflow.
- The offline service worker now refreshes same-origin assets from the network before falling back to its cache, so rebuilt UI assets do not remain stale while offline support is preserved.
- Removed the unused replacement-view module from the viewer asset inventory and extension assembly so the five-view release package contains only files referenced by the active shell.
- All MCP tool responses now use a shared iterative JSON serializer instead of native recursive stringification. Deep canonical values serialize without call-stack failure, cycles become `null`, prototype-named keys remain data, repeated non-circular references retain their content, and pretty-print indentation stops growing after 20 levels so whitespace cannot become quadratic.
- MCP redaction now traverses report objects and arrays with an iterative worklist, so deeply nested parsed values do not exhaust the JavaScript call stack. Circular references become serializable `null` boundaries, repeated references still reuse their redacted clone, and reuse is isolated by redaction policy so a value first seen in an ordinary field cannot weaken masking under a fully sensitive field.
- Repository formatting now discovers maintained tracked and untracked TypeScript, module-script, Markdown, and YAML files from Git instead of relying on a small hand-written file allowlist. Generated/UI bundles, research notes, and lockfiles remain excluded; `.vscode-test/` downloads are ignored; and a scope regression test protects representative parser, host, test, script, configuration, and documentation paths.
- Normalized timelines and canonical trace events now expose `durationNs`/`durationMs: null` for `missing_end`, `orphan_end`, `closed_by_exception`, `closed_at_truncation`, and `depth_limit` records even when parser recovery assigned a synthetic closure timestamp. Intentionally bounded pseudo-spans with `not_applicable` pairing, such as managed-package entry windows, retain measured durations.
- Transaction relative-time boundaries now come from `EXECUTION_STARTED`/`EXECUTION_FINISHED` event nanoseconds, with parser-relative timestamp fallback only when event evidence is unavailable. Duration fallback no longer subtracts wall-clock milliseconds-since-midnight from relative nanoseconds, and an observed same-timestamp transaction remains an exact zero duration.
- Repeated-SOQL timing summaries now follow the report's exact-or-unknown contract: `totalDurationMs` and `avgDurationMs` are `null` when any grouped execution is unmeasured, negative, non-finite, or makes the aggregate non-finite. Heap namespace totals accumulate through a map before producing ordinary report objects.
- Report normalization now reads only own parser-result fields, so inherited prototype values cannot become events, namespaces, diagnostics, governor evidence, or other report facts. Component histograms and event indexes accumulate untrusted dimension names through maps before producing ordinary JSON objects.
- Debug-level quality assessment now trims configuration values, consolidates duplicate categories with last-setting-wins semantics, and emits explicit warnings when foundational Apex Code or Database configuration evidence is absent. CPU attribution accumulates untrusted CPU-type and namespace keys through maps before producing ordinary report objects and remains single-pass for large span collections.
- Dynamic Salesforce ID-prefix learning now uses an evidence hierarchy. Unambiguous literal `Id = '…'` and `Id IN ('…')` SOQL predicates outrank variable-name heuristics; conflicting query or variable evidence leaves the prefix unresolved, and canonical standard prefixes remain immutable. Predicate scanning excludes relationship-subquery, comment, string, and foreign-key IDs and handles large literal lists without repeated full-query scans.
- Governor burn rates and phase headroom now use a single consistent namespace, preferring `default` and falling back to the earliest observed namespace when necessary. Phase snapshot lookup is binary instead of rescanning the trajectory, and namespace aggregation uses a prototype-free dictionary for untrusted namespace names.
- The two intentional 25 MiB parser/worker boundary regressions now have focused 15-second test budgets, preventing concurrent coverage instrumentation on slower runners from tripping Vitest's unrelated five-second default while retaining the production size boundary and global test timeout.
- Cumulative-profiling extraction now walks the event collection directly instead of first allocating a filtered copy. Valid execution counts, elapsed milliseconds, and Apex source lines share the canonical complete safe-integer parser and accept correctly grouped integer evidence.
- Execution-context detection now collects event signals in one pass and evaluates canonical Future, Queueable, Batch Apex, Platform Event, and trigger evidence before derived class-name heuristics. Legacy Batch/Scheduled fallbacks require meaningful class-name suffixes, preventing incidental names such as `TriggerHandler`, `BatchUtilities`, and `ScheduledApexUtilities` from changing the phase model.
- Per-phase governor-limit evidence now locates before/after snapshots with binary search over the sorted timeline instead of rescanning every snapshot for every phase. Duplicate timestamps, inclusive phase boundaries, empty-window fallback, and unknown evidence semantics remain unchanged.
- Execution-phase attribution now buckets SOQL, event-backed DML, and variable assignments in one pass per collection instead of rescanning each complete collection for every phase. Half-open phase boundaries, final-span fallback behavior, source ordering, exact-or-unknown row totals, and data-flow lineage remain unchanged.
- Managed-package impact analysis now aggregates every namespace in one span pass and one event pass instead of filtering and mapping the complete collections once per package. Duplicate namespace declarations are normalized, temporary per-package arrays are eliminated, and exact-or-unknown duration and completed-row semantics remain unchanged.
- Recursive-trigger detection now checks same-trigger ancestry without comparing every pair of trigger spans. Each retained trigger group keeps at most 50 unique Apex source lines and 50 bounded raw evidence samples, with occurrence counts and truncation flags in `evidenceMeta`; analysis retains at most `limits.recursiveTriggers` groups (default 50) and exposes full group-count metadata in `recursiveTriggerAnalysis.meta`.
- Parser log-issue aggregation is now bounded and linear-time. At most 200 issues are retained, summaries are capped at 500 characters, descriptions and raw issue evidence at 2,000 characters, and overflow occurrences are represented by one timed aggregate plus `logIssueOverflowCount`; retained-summary lookup uses a map and issues are sorted once after parsing instead of after every insertion. Report construction feeds raw errors, parser issues, and synthetic warnings into a bounded earliest-N collector instead of materializing complete intermediate arrays; `limits.errorItems` defaults to 500 while `errors.count`, `errors.truncated`, and `errors.limit` preserve full-count and truncation metadata.
- The low-level core parser now enforces the same 25 MiB UTF-8 ceiling as every maintained host before splitting input into log lines. `MAX_LOG_BYTES` is exported as the canonical boundary and is reused by browser and CLI workers, the CLI server, MCP file ingestion, and the VS Code source adapter; host checks remain in place for earlier, context-specific errors.
- Canonical insights and offline-report assembly now clone JSON-like parser values with an iterative, cycle-aware serializer boundary. Deep structured payloads no longer depend on the JavaScript call stack; circular references are bounded, non-finite numbers become `null`, unsupported object properties are omitted, and unsupported array entries become `null` before report delivery.
- Salesforce ID lineage and structured relationship-graph traversal now use iterative, cycle-aware worklists instead of recursive object descent. Deep valid assignment payloads no longer depend on the JavaScript call-stack limit, and cyclic legacy objects cannot loop indefinitely; record provenance, relationships, truncation metadata, and exhaustive ID discovery remain intact.
- Core numeric evidence parsing and normalization now use one canonical complete-token helper for rows, cursor offsets, Named Credential sizes/timings/status codes, multiline governor usage, flattened vendor events, and offline-report fallback fields. It accepts plain or correctly three-digit-grouped nonnegative safe integers and rejects malformed grouping, decimal/scientific spellings, partial tokens, and precision loss consistently across parser and report layers.
- Parser and report tokenization now uses a bounded pipe-field scanner whose final token retains the exact remaining payload. Pathological delimiter-heavy records can no longer allocate one array entry per pipe, while generic event text, structured variable values, heap-address removal, cursor details, and user metadata retain their existing semantics.
- Browser and CLI parser workers now enforce the 25 MiB UTF-8 input boundary with an allocation-free byte counter instead of creating a second full-size encoded buffer before parsing. The core package exports the same `utf8ByteLength()` helper, including `TextEncoder`-compatible handling of lone UTF-16 surrogates.
- Named Credential response matching and Named Credential-to-callout correlation now use monotonic, order-preserving cursors instead of repeated array searches and response splices, keeping integration analysis linear on callout-heavy logs.
- Repeated-SOQL analysis now accumulates timestamps during its grouping pass instead of rescanning the full query list for each pattern. Literal normalization handles Apex backslash escapes, doubled quotes, and dotted bind expressions, preserving N+1 detection when values contain apostrophes.
- Browser-extension and CLI parser workers now reject empty or larger-than-25-MiB raw-log messages before parsing. Extension file and captured-page paths, plus the CLI server, enforce the same hard boundary before expanding raw lines or transferring content.
- Browser URL loads now enforce the 25 MiB limit while streaming the response, before JSON parsing, raw-line expansion, or worker transfer. Handoff parameters accept only credential-free HTTP(S)/file `.log` URLs and the two generated storage-key formats; oversized detected pages are not copied into extension storage.
- Log-completeness analysis now scans raw lines in place instead of joining the full log into another large string, reducing peak memory use for browser and extension reports without changing truncation detection.
- Timeline normalization now traverses parser trees iteratively, preserving deeply nested events beyond the parser recursion safety boundary without risking a JavaScript call-stack overflow. Logs without compact DML records also avoid an unnecessary full-text split and rebuild before parsing.
- The CLI server now returns an explicit close handle instead of installing process-wide signal handlers or terminating its host process. Single-file log listings reuse known metadata, and `HEAD` requests no longer read complete logs or viewer assets into memory.
- Coverage validation now enforces higher repository floors plus focused thresholds for the parser/report core, MCP tool handlers, and directly unit-testable VS Code contracts, preventing one well-tested package from masking regressions in another.
- Viewer hosts now use one `showOfflineReport()` boundary to hydrate and display canonical reports, preparing the shared interface for a proposed VS Code extension without changing the five-view workflow.
- MCP log inputs are capped at 25 MB and file validation distinguishes path segments from harmless dots in file names.
- Parser pairing distinguishes orphan exits and truncation closures, marks inferred durations as partial, and preserves over-depth subtrees through an iterative fallback after the 500-level recursion limit.
- Reports expose evidence-backed asynchronous continuation clues without claiming that a related Queueable, Future, Batch Apex, or event-service transaction is present.
- The UI now labels clickable raw-file positions as **Log line** and non-clickable code positions as **Apex source line**. Evidence navigation no longer falls back to ambiguous source coordinates, and repeated raw lines prefer a parser-declared coordinate only after verifying the raw text.
- Browser analysis views now group repeated failure evidence, cap the initial execution story at 200 rows, avoid pre-rendering hidden query tables, and show the total raw-log result count.
- Governor-limit cards show the actual percentage and overage instead of masking values above 100%, and identify default-namespace values as transaction limits rather than org limits.
- The Diagnostics view no longer repeats the generic issue table.
- Browser release checks now cover the five-view workflow, large-log rendering limits, evidence terminology, first-run copy, and assembled offline assets. `pnpm test:coverage` records HTML and JSON coverage reports and enforces repository-wide regression floors.
- Log quality checks remain part of analysis but no longer show a routine success panel. Triage displays **Log quality warning** only when missing or uncertain evidence can affect interpretation; captured exceptions use the clearer **Failure context** heading.
- Analysis tables now separate evidence coordinates into compact **Source line** and **Log line** columns. Cells show only the number; both columns hug the right edge, and the clickable log-line evidence link is consistently last.

- The release workflow now packages the VS Code extension and attaches the `.vsix` to the GitHub Release alongside the browser archives, and publishes `docs/releases/<version>.md` as the release notes when that page exists instead of always generating notes from commits.

- Canonical transaction timing now requires a complete `EXECUTION_STARTED`/`EXECUTION_FINISHED` pair. Replacement symlinks and special files cannot be served after validation, files that grow during a request remain capped one byte beyond 25 MiB, and small logs begin with a proportional 64 KiB buffer rather than reserving the full limit.

- The depth-limit fallback no longer consumes an exit owned by an earlier fallback frame or by the recursive ancestor stack as an orphan child. It now unwinds only intervening entries with missing ends, preserves the exit for its actual owner, and allows the outer method and transaction to close normally.
- The iterative parser fallback beyond 500 nested events now runs typed end hooks and recalculates matched child durations, preserving exact SOQL/SOSL row evidence, callout response evidence, method metadata, and timing without recursive stack growth. Every frame still open when the fallback reaches EOF is marked `depth_limit` and partial rather than retaining a zero duration or `not_applicable` pairing.
- Partial parser recovery boundaries no longer become apparently exact span timing. Truncated methods, unmatched Formula/RLM/Automation begins, ancestor-unwound database work, exception closures, and depth-limited spans retain their pairing and evidence metadata but cannot contribute synthetic durations to traces, CPU attribution, phase timing, or package summaries.
- The low-level wall-clock parser now enforces the canonical Salesforce `HH:MM:SS` clock with 1–9 fractional digits and a following relative-timestamp field. One-digit hours, impossible components, fractions beyond nanosecond precision, and incomplete prefixes leave `ApexLog.startTime` unknown instead of producing plausible metadata. `overview.topMetrics.relativeTimeNs` no longer mixes this wall-clock value with relative event timestamps.
- Generic dotted code-unit names now promote a leading token to a managed-package namespace only after independent parser evidence establishes that namespace, preventing inner classes such as `Outer.Inner.run()` from creating a fake `Outer` package. `__sfdc_trigger/Object/Trigger` code units now parse their selected descriptor rather than an unrelated optional field, keep the descriptor as trigger identity, leave standard object names such as `Account` in `default`, and infer packages only from a managed custom-object name or an already-established trigger prefix.
- Custom object and platform-event API names now require both a namespace separator and a custom-type suffix before the leading token is treated as a managed-package namespace. Unmanaged names such as `Invoice__c` and `Order_Event__e` remain in the default namespace, while `pkg__Invoice__c` and `pkg__Order_Event__e` retain `pkg`; Event Service spans, component counts, and managed-package impact no longer invent packages from unmanaged API names.
- Heap allocation byte fields now require complete, correctly grouped positive safe-integer tokens; numeric prefixes with suffixes and malformed grouping are ignored instead of becoming allocations. Heap namespaces named `__proto__` or `constructor` no longer corrupt or crash namespace aggregation. Visualforce viewstate warnings likewise reject negative, fractional-byte, partial, non-finite, and unsafe converted sizes instead of extracting plausible numbers from malformed evidence.
- Event types, namespaces, categories, and debug categories named `__proto__`, `constructor`, or another JavaScript prototype property no longer corrupt component counts or crash event-index construction. These labels remain ordinary own keys in canonical report objects.
- Debug-level rank lookup and CPU attribution no longer treat inherited object properties such as `constructor` or `__proto__` as valid levels or accumulator entries. CPU/package duration and row aggregation now validates each operand before addition, so negative or non-finite evidence cannot cancel earlier positive values into a plausible total.
- Variable-name sObject inference now tokenizes camelCase, acronym, underscore, and plural Apex identifiers instead of matching arbitrary substrings. Ordinary names such as `policy`, `shoppingCart`, `showcase`, and `abuser` no longer become OpportunityLineItem, Opportunity, Case, or User records.
- Governor burn-rate analysis no longer derives rates across different namespaces, invents consumption from same-timestamp snapshots, reports negative rates after a counter reset, or exposes negative projected headroom after a limit is exhausted. Hostile namespace names such as `__proto__` and `constructor` are retained as ordinary report keys without prototype collisions.
- SOQL Explain-plan cardinality, sObject cardinality, and relative-cost fields now require complete numeric tokens. Fractional integer counts, malformed comma grouping, overflow, and incomplete exponent spellings remain unknown instead of being accepted from a numeric prefix. Cumulative-profiling counts, timings, and source lines apply the same no-prefix rule.
- Execution-context overrides now require an own declared context key. Prototype-chain names such as `constructor`, `toString`, and `__proto__` are rejected instead of producing malformed override objects.
- MCP filesystem integration tests now create collision-resistant temporary directories and remove them after every case, including the 25 MiB boundary fixture. Repeated validation runs no longer leak large files into the operating-system temporary directory or eventually fail unrelated tests with `ENOSPC`.
- Salesforce record-graph and dynamic-prefix extraction now distinguish complete ID fields from searchable prose. Direct record IDs, ID lists, map keys, and foreign-key fields must be exact 15- or 18-character alphanumeric tokens; strings merely containing an ID cannot become fake records or relationships. A valid map key now supplies the record ID when its value has a missing or malformed `Id`, and `WHERE Id IN (...)` prefix learning processes every literal ID instead of only the first.
- Execution-phase data flow now uses the same half-open time windows as database and heap attribution. A variable assignment at the next phase's start belongs only to that phase, preventing duplicated assignments and false input lineage. Salesforce record IDs used as object/map keys are now collected alongside values, and strings containing multiple IDs retain every match, so record assignments report consistent `recordsProcessed`, `inputIds`, and `outputIds`.
- Heap analysis no longer loses precision when individually valid allocation values overflow a derived sum. Transaction allocation/deallocation/net values, cumulative peak and watermark samples, line hotspots and averages, namespace totals, and phase totals now become `null` when their exact byte value cannot be represented safely. Heap allocations at an adjacent phase boundary use the same half-open window rule as database phase metrics and are counted only in the next phase.
- Timestamp ordering validation now observes every retained physical event, including ordinary debug, database, callout, and exit records instead of only nested parent entries. Regressions are grouped into one direct issue with exact occurrence and first/last timestamp metadata; a paired end earlier than its start exposes `durationNs: null`, is marked partial, and cannot retain a negative internal duration.
- Malformed SOQL, SOSL, and DML row fields no longer collapse to observed zero. Typed database spans retain an explicit row-evidence flag, so missing, nonnumeric, negative, fractional, overflowed, partially numeric, or incorrectly comma-grouped payloads expose `rows: null` and cannot create false empty-query or no-op-DML findings; a valid `Rows:0` remains distinct observed evidence. Cursor row and offset extraction applies the same complete-token rule. Named Credential metrics with malformed grouping remain `null`, and a labeled HTTP status code cannot be accepted from the first three digits of a longer number. The low-level `parseRows()` helper returns `null` for unparseable input instead of the misleading zero fallback.
- SOQL `aggregations` now follows the report's exact-or-unknown evidence contract. An observed safe nonnegative `Aggregations:` integer retains its value, while missing, empty, malformed, or precision-losing fields expose `null` instead of falsely reporting zero; the typed query and its full text remain available. Empty query-plan numeric fields likewise remain unknown rather than being coerced to zero.
- Browser-extension and CLI viewer workers now require an optional `fileId` to be a non-empty string before parsing, preventing malformed messages from producing non-string report source metadata. The unused `SET_CONFIG` worker message and its persistent mutable state were removed because maintained hosts never sent it, and the CLI worker protocol now has direct tests matching the browser worker's invalid-message and canonical-report coverage.
- VS Code report workers now derive source bytes from the actual UTF-8 log text instead of trusting duplicated request metadata. Empty and oversized worker inputs are rejected before parsing, Unicode report sizes are exact, and the worker protocol no longer carries a caller-controlled byte count that can disagree with report contents.
- CLI and browser-extension parser workers now share one core message-validation and report-construction path while retaining their host-specific source attribution and lifecycle adapters.
- VS Code parser workers now validate request IDs, message types, file names, and log-text types before parsing. Malformed correlated requests return an immediate typed error instead of being silently ignored or coerced into unintended strings, and the testable request processor covers ignored, invalid, failed, and successful protocol paths.
- VS Code parsing now rejects immediately if a worker exits before returning its requested report, including an unexpected clean exit. A lost response can no longer leave analysis pending until the 120-second timeout; malformed responses for the active request are rejected at the protocol boundary, unrelated request IDs remain isolated, and synchronous request-dispatch failures terminate and release the worker instead of leaking active parser state.
- VS Code contextual log detection now measures the bounded 64 KiB prefix using exact UTF-8 bytes and the source's real LF, CRLF, or CR separators. Final unterminated lines no longer receive a synthetic newline, and a pathological single line cannot make discovery scan beyond the byte budget.
- `ApexLog.size` and every MCP-generated report now use the canonical allocation-free UTF-8 byte counter instead of JavaScript UTF-16 string length or an allocated `TextEncoder` buffer. Non-ASCII text, valid surrogate pairs, and lone surrogates produce the same exact byte count across the parser, browser/CLI/VS Code workers, MCP tools, and report metadata without duplicating near-limit log contents in memory. - Relative timestamp zero is now treated as observed parser evidence rather than a missing value. Initial public release of Apex Log Insights as an open-source project.

### Added

- **Core parsing engine** (`@apex-log-insights/core`) — zero-dependency TypeScript library that parses Salesforce Apex debug logs into structured JSON reports. Extracts execution timelines, SOQL/DML analysis, governor limit tracking, callout details, named credentials, trigger cascades, managed package impact, and 20-phase lifecycle mapping
- **CLI** (`@apex-log-insights/cli`) — command-line interface that opens Apex debug logs in a local browser viewer. Supports single files, directories of logs, custom ports, and headless mode
- **MCP server** (`@apex-log-insights/mcp`) — Model Context Protocol server exposing five tools (`parse_apex_log`, `analyze_performance`, `analyze_soql`, `analyze_governor_limits`, `summarize_log`) for AI-assisted log analysis with Claude, Cursor, and other MCP-compatible tools
- **Browser extension** (`@apex-log-insights/browser-ext`) — available for Chrome, Edge, and Firefox. Detects `.log` files opened in the browser and offers instant analysis. Includes drag-and-drop file loading, URL source loading, and storage persistence
- **Offline HTML viewer** — zero-dependency vanilla JS viewer with five structured views: Triage (verdict + key metrics), Execution (20-phase timeline), Data & Limits (SOQL/DML/callouts/governor limits), Diagnostics (context detection, trigger cascades, managed package impact), and Evidence (full raw log with search and filtering)
- **Evidence linking** — every SOQL query, DML operation, callout, and diagnostic warning links directly to the exact line in the raw log
- **N+1 SOQL detection** — automatically flags queries executing inside loops
- **Governor limit burn rate** — per-phase breakdown of CPU, heap, SOQL, DML, and callout consumption
- **Mixed DML detection** — warns when setup and non-setup objects are modified in the same transaction
- **Recursive trigger detection** — flags triggers firing multiple times in a single transaction
- **Debug level quality scoring** — rates log completeness based on captured event types
- **PHI/PII redaction** — masks email addresses, Salesforce IDs, phone numbers, and custom names before copying log content (browser extension)
- **MCP PII redaction** — opt-in `redact: true` parameter on all MCP tools masks Salesforce IDs, emails, phone numbers, debug messages, named credentials, SOQL bind values, and callout URL parameters before results reach the AI client. Structural metadata (class names, field names, sObject types, governor limits, durations) is preserved for meaningful analysis
- **Content script auto-detection** — extension intercepts `.log` URLs in the browser (including Salesforce debug log download links) and offers to analyze them automatically
- **Execution context detection** — identifies runtime context automatically: anonymous Apex, queueable, future method, batch execute, scheduled, platform event, synchronous trigger, and Apex class
- **Monorepo architecture** — pnpm workspaces with shared `tsconfig.base.json`, unified version management via `sync-versions.mjs`, and automated extension UI assembly from viewer sources
- **Build and quality tooling** — package and extension builds, dependency/security auditing, static bug detection, tests, typechecking, and linting
- **Multi-browser extension builds** — `build:chrome`, `build:edge`, and `build:firefox` scripts with explicit version selection and zip/xpi packaging
- **Extension UI assembly** — `assemble-extension-ui.ts` merges viewer sources with extension-only overlays so viewer changes propagate automatically

- **Documentation** — README, contributor and style guides, package guides, feature reference, and agent context files

### Security

- Path traversal protection in CLI server using `path.resolve()` with directory separator prefix check
- XSS prevention via HTML escaping in browser extension display functions
- Path validation in MCP `readLogFile` — rejects `..` traversal, absolute paths, null bytes; enforces `.log` extension; 30-second read timeout
- MCP tool input validation using `typeof` checks instead of unsafe `as` casts
- `pnpm audit` integrates dependency vulnerability scanning, secret detection, and ESLint security rules

### Privacy

- **CLI, browser extensions, and viewer**: All processing runs locally. No servers, no uploads, no accounts, no telemetry. Log data never leaves the user's machine
- **MCP server**: All parsing runs locally via `@apex-log-insights/core` (zero network requests from the MCP server). Structured results are passed to the connected AI client via stdio. If the AI client uses a cloud service, parsed report data (SOQL queries, class names, namespace info) will be transmitted through the AI's pipeline. Use `redact: true` on any MCP tool to mask sensitive values before they reach the AI
