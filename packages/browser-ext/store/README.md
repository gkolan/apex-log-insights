# Browser store documentation

Use this folder to prepare and review public browser-store submissions. The documents separate customer-facing claims from internal release checks so reviewers can verify every statement before publishing.

## Documents

| Document                                        | Purpose                                                                     |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| [Store listing](listing.md)                     | Product name, summary, detailed description, permissions, and support links |
| [Privacy policy](privacy-policy.md)             | Data processing, local storage, permissions, retention, and user controls   |
| [Screenshot guide](screenshots-guide.md)        | Safe fixture, capture sequence, image sizes, and captions                   |
| [Release notes](release-notes.md)               | Concise store-facing changes by version                                     |
| [Submission checklist](SUBMISSION-CHECKLIST.md) | Final package, privacy, permission, asset, and review checks                |

## Submission order

1. Build and test the release by following the [release guide](../../../docs/development/releasing.md).
2. Update the listing and release notes with claims that match shipped behavior.
3. Capture screenshots from the approved synthetic fixture.
4. Compare data-use answers with the privacy policy and actual permissions.
5. Complete the submission checklist before uploading the package.

Do not include customer logs, organization names, credentials, or real Salesforce record IDs in store assets.
